# 완료·차단 확인

1. 현재 작업 JSON·상태와 필요한 완료 기준을 확인한다. 관련 테스트부터 실행하되 합의된 필수 회귀·통합 검증까지 수행한다. 이전 성공은 현재 변경의 검증을 대신하지 않는다. 요약의 성공·출력 잘림을 원래 명령의 성공 근거로 삼지 않는다. 명령·실행 위치·종료 코드·실패·경고·원본 증거 경로를 확인한다. 검증을 통과시키려고 테스트·안전 규칙을 약화하지 않는다.
2. 변경 범위·사용자 변경 보존·오류/경계 조건을 자체 리뷰한다. 모든 완료 기준 ID에 현재 변경 상태에서의 통과·실패·미검증과 증거 경로를 연결한다. 미실행 검증은 미검증으로 표시한다. 실패·리뷰 문제는 복구 한도 안에서 task-resume으로 수정하고, 미충족 상태를 완료라고 하지 않는다. 사용자나 플랫폼 때문에 실행할 수 없으면 차단 사유로 기록한다.
3. 실제 설계·JSON·상태 경로, 복구 횟수·남은 위험을 갱신한다. 완료·복구 한도 소진·실제 차단 중 어느 상태인지 구분한다. 최종 보고는 변경 이유·수정 파일·테스트 결과·잔여 위험으로 간단히 쓰되 기준별 결과·명령·종료 코드·증거 경로와 차단 시 필요한 결정을 포함한다. 긴 상세 근거는 상태·이력을 참조한다. 사용자 지정 보고 형식은 존중한다.
