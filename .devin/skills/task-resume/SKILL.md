# 재개·복구

1. 사용자 지정 또는 현재 작업의 실제 JSON·상태 파일과 필요한 설계 부분을 읽는다. 현재 단계·전역 제약·모든 완료 기준의 상태·미검증·미해결 위험·승인 경계·누적 복구 횟수를 복원하고 초기화하지 않는다. 같은 작업인지 불명확하면 질문한다. 계약 자체가 없거나 다른 작업이면 task-start 절차로 전환한다.
2. 설계·안전 규칙·관련 파일·실행 조건의 변경 여부와 기존 증거의 유효성을 다시 확인한다. 확인할 수 없으면 관련 구간을 다시 읽고 검증한다. 근거 누락·참조 오류는 미검증으로 표시하고 필요한 범위만 재조사·검증한다. 이력 전체를 다시 읽지 않는다.
3. 실패 원인·기존 시도·로그를 확인한다. 최초 실패 이후 수정·재검증을 복구 1회로 센다. 매 복구 전에 현재 작업 JSON의 maxRetries와 누적 횟수를 확인·기록한다. 원인 근거 없이 같은 명령을 반복하지 않는다. 한도 소진·권한/범위 확대·해소 불가 차단이면 중단하고, 아니면 수정·재검증을 이어간다.
4. 상태는 현재 판단과 다음 행동의 요약으로 유지한다. 과거 상세 기록으로 커지거나 단계가 바뀔 때만 상세 근거를 승인된 프로젝트 내부 별도 이력에 보관하고 참조 경로·내용을 확인한 뒤 요약한다. 전체 이력 목록은 별도 색인에 두고 필요한 참조만 남긴다. 현재 근거·기준별 상태·위험·승인 경계·누적 복구 횟수는 요약·재개·단계 전환 시에도 초기화하지 않는다. 기존 기록을 덮어쓰거나 삭제하지 않고 길이 제한 때문에 필요한 근거를 버리지 않는다. 매 턴 재요약하지 않는다.
5. 변경·검증 결과와 다음 행동을 상태에 갱신한다. 유효한 맥락은 재사용하고 승인 범위에서 계속 진행한다. 실제 중단 또는 완료 보고 직전에는 task-finish 절차로 확인한다.
