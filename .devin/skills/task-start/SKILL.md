# 작업 준비

1. 사용자가 설계·JSON·상태 파일을 직접 작성하도록 요구하지 않는다. 관련 코드·테스트와 필수 프로젝트 규칙을 확인한다. 자동 import가 꺼져 있어도 AGENTS.md·CLAUDE.md 등의 관련 계약·보안·빌드·테스트·금지 규칙을 보존한다. 사용자만 결정할 범위·완료 기준·권한과 상충하는 결정만 질문하고, 코드로 확인할 사실은 조사한다.
2. 사용자 지정 경로를 우선한다. 기본은 `docs/devin/DESIGN.md`, `.devin/task.json`, `.devin/state/STATE.md`다. 기존 파일이 같은 작업의 목표·범위·기준과 일치하면 재사용하고 누락분만 보완한다. 다른 작업이거나 소유가 불명확한 파일은 덮어쓰지 않는다. 새 작업은 고유한 `.devin/tasks/<task-id>/` 아래 `DESIGN.md`, `task.json`, `state/STATE.md`를 쓴다. 실제 프로젝트 내부 경로인지 확인하고 심볼릭 링크를 경유한 생성·강제 덮어쓰기는 하지 않는다. 재개에 여러 후보가 있으면 질문한다.
3. 새 계약에 필요한 경우에만 `docs/devin/DESIGN.template.md`·`docs/devin/STATE.template.md`·`.devin/task.example.json`을 참고한다. 실제 요청에 맞는 단일 설계에 범위·결정·순서·완료 기준 ID·검증·중단 조건을 채우고 JSON은 짧게 참조한다. 사용자 설계는 충분히 읽고 보존하며 빈 템플릿을 완성된 설계로 취급하지 않는다. 양식 안내만 제거하고 사용자 기록은 보존한다.
4. 실제 프로젝트에서 확인한 검증 명령을 사용하고 예제의 하네스 자체 검사로 프로젝트 검증을 대체하지 않는다. 필수 검증 방법을 정할 수 없으면 질문한다. 새 작업 기본은 `maxRetries: 3`, `allowPaidExecution: false`, JSON 기준 `stateFile: state/STATE.md`다. false는 추가 유료 호출 금지이지 Local 청구 차단 설정이 아니다. 합의된 다른 복구 상한은 유지하고 설계·JSON·상태 경로와 기준을 맞춘다. Node가 있으면 `node .devin/tools/validate-task.cjs <실제 작업 JSON 경로>`로 검사한다. Node가 없으면 설치·권한 확대를 강요하지 않고 스키마 수동 확인과 도구 검사 미실행을 기록한다.
5. 실제 설계·JSON·상태 경로와 다음 행동을 상태에 남긴다. 준비 중 차단도 기록한다. 기존 누적 복구 횟수는 재사용·부분 준비 때도 초기화하지 않는다. 준비 후 구현·검증을 이어가며 재개 승인을 요구하지 않는다.

## 실행 중 조회
파일·함수·재현 조건에서 시작해 현재 단계에 필요한 부분부터 읽는다. 전역 제약은 유지하고 단계 전환 때 의존 관계·영향 범위를 확인한다. 검색 결과 없음·출력 잘림·상충하는 증거로 근거가 부족하면 검색·읽기 범위를 확장하며 고정된 읽기 횟수 때문에 조사를 중단하지 않는다. 로그의 필요한 실패 원인·스택 트레이스만 확인하고 비밀정보는 마스킹한다. 요약 도구의 성공을 원래 명령의 실패와 혼동하지 않는다. 의미 있는 변경·검증·차단 때만 상태를 갱신하고 정상 작업 중 Skill을 반복 호출하지 않는다.
