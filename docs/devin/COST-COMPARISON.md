# 비용 비교 절차 — 현재 실행 금지

현재 워크플로우에서는 유료 실행을 하지 않는다. 아래 절차는 추후 사용자와 회사의 비용 승인을 받은 후 사람이 실행한다. 승인된 플랫폼 한도 설정이 없으면 실제 지출 상한을 강제할 수 없다는 점을 먼저 확인한다.

## 비교 설계
- 동일 저장소 리비전과 깨끗한 작업 사본에서 같은 독립 작업을 사용한다. 기존 사용자 파일을 삭제하거나 리셋하지 않는다.
- 동일한 충분한 설계 문서·완료 기준·검증·복구 상한을 사용한다.
- A는 기존 Pi 경유, B는 Devin 직접 실행이다. 한 번의 비교를 전체 성능으로 일반화하지 않는다.
- 가능한 경우 같은 실제 모델·추론 설정을 사용한다. Adaptive 여부, 모델 변경, 캐시 상태, 컨텍스트 크기와 세션 길이 차이를 기록한다. 설정을 확인할 수 없으면 unknown으로 남긴다.
- 사용자 메시지 과금과 내부 모델 호출 과금을 구분한다. 회사 산식을 확인하지 않고 메시지당 단가를 추정하지 않는다.
- 승인된 소규모 작업으로 먼저 비교한다. 작업별 총예산·실행 중단 담당자·관찰 주기를 정한다. 한도 초과나 확인 불가 시 추가 실행을 하지 않는다.

플랫폼 사용 내역이 제공하는 실제 비용만 기록한다. 관측 불가능한 내부 호출·주입량·비용은 unknown이며 0이 아니다. 메시지 수 감소만으로 크레딧 감소를 주장하지 않는다. 원시 로그나 인증키를 문서에 붙이지 않는다.

## 결과 해석
두 실행 모두 동일한 완료 기준을 통과했는지 먼저 비교한다. A의 실제 비용이 0보다 크고 두 비용이 같은 단위로 확인될 때만 `(A-B)/A*100`을 계산한다. 하나라도 unknown이면 절감률도 unknown이다. 더 적은 메시지가 더 긴 실행·더 비싼 모델 사용을 유발할 수 있다. 단일 실행은 인과관계나 일반적인 절감률의 증거가 아니다.
