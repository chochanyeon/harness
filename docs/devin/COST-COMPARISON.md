# 토큰·비용 비교 절차 — 현재 유료 실행 금지

## 목표와 비교 조건
동일한 완료 기준·변경 품질·검증 수준을 유지하면서 장기 자율 실행을 끝낼 때까지 쓰는 총 입력·출력 토큰을 줄이는 것이 목표다. 이 문서는 비교 준비용이며 현재 작업에서는 유료 Devin/LLM 호출을 실행하지 않는다. 실제 비교는 추후 사용자와 회사의 비용 승인 후 수행한다. 플랫폼 한도가 확인되지 않으면 지출 상한을 강제할 수 없다.

- A: 변경 전 Devin 직접 실행, B: 변경 후 Devin 직접 실행. 지침·템플릿 버전과 작업 입력을 보관한다. 기존 Pi 경유 비교는 별도 실험으로 분리한다.
- 기본 비교 환경은 Desktop의 Devin Local로 고정하고 버전·Normal 모드·권한 정책을 기록한다. 설계·JSON·상태를 스스로 준비하는 초기 토큰과 권한 요청·실패 후 복구 비용도 포함한다. CLI 또는 Cascade 실행과 섞어서 비교하지 않는다.
- 동일 저장소 리비전의 분리된 작업 사본에서 같은 목표·범위·완료 기준·필수 검증·복구 상한을 사용한다. 기존 사용자 파일을 삭제하거나 리셋하지 않는다.
- 가능한 경우 같은 모델·추론·Adaptive 설정으로 비교한다. 실행 순서·캐시·초기 컨텍스트·세션 길이·네트워크/도구 조건 차이를 기록한다. 공통 설계의 의미는 보존하고 탐색 시작점·자료 발췌 등 입력 구성만 변경 사항으로 명시한다.
- 처음에는 승인된 소규모 작업으로 안전성을 확인하고, 효과 비교에는 여러 단계·반복 검증·재개가 포함된 승인된 장기 자율 실행 작업을 사용한다. 초기 설계 이해 비용과 이후 반복 읽기·출력 비용을 분리하고 초반·중반·후반의 상태 크기·읽기량·이력 조회량을 관측 가능한 범위에서 기록한다. 짧은 작업만으로 장기 효율을 판단하지 않는다.
- 작업들을 반복 비교하고 실행 순서를 교차한다. 실패·중단·재시도도 빠짐없이 포함한다. 추가 재개 메시지와 재실행·새 세션의 토큰을 같은 작업에 합산한다.
- 작업별 총예산·중단 담당자·관찰 주기를 사전에 정한다. 한도 초과나 확인 불가 시 추가 실행을 하지 않는다.

토큰은 플랫폼 사용 내역의 측정 단위와 집계 범위를 기록한다. 캐시 토큰이 입력에 포함되면 다시 더하지 않는다. 숨겨진 추론이나 내부 호출을 관측할 수 없으면 해당 항목과 총량의 완전성을 unknown으로 표시한다. 문자 수·로그 줄 수·사용자 메시지 수를 토큰이나 비용으로 환산하지 않는다. 원시 로그나 인증키를 문서에 붙이지 않는다.

## 결과 해석
1. 두 실행의 완료 기준·회귀 결과·변경 품질을 먼저 비교한다. 필수 검증 미실행·미검증은 성공이 아니다. 품질 동등성이 확인되지 않으면 동일 결과의 효율 개선이라고 주장하지 않는다.
2. 전체 시도의 완료율과 토큰 합계를 함께 보고한다. 성공한 작업당 총토큰은 실패·중단 시도까지 포함한 전체 토큰을 성공 작업 수로 나눈다. 성공 수가 0이거나 집계가 불완전하면 unknown이다. 성공끼리의 개별 비교만으로 실패율을 감추지 않는다.
3. 같은 단위의 완전한 토큰 합계가 있고 A가 0보다 클 때만 `(A-B)/A*100`을 계산한다. 비용 절감은 실제 청구 단위로 별도 계산한다. 하나라도 unknown이면 해당 절감률도 unknown이다.
4. 단일 작업이나 정적 문구 검사는 절감 효과의 증거가 아니다. 캐시·모델·작업 난이도 차이를 밝혀야 하며 토큰 감소가 비용 감소를 보장하지 않는다.
