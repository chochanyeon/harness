# 단일 작업 설계

Devin Local이 일반 작업 요청과 좁은 코드 조사를 바탕으로 아래 항목을 구체화한다. 사용자가 직접 작성할 필요는 없으며, 기존 설계가 있으면 보존·재사용한다. 빈 항목이나 결정되지 않은 필수 사항은 실행 전에 해결한다. 이 템플릿은 JSON 검사 도구가 검사하지 않으므로 사람 또는 실행 주체가 내용 충족 여부를 검토한다.

## 1. 맥락과 문제
현재 동작, 필요한 변경, 사용자 가치, 알려진 사실과 미확인 가설을 구분한다.

### 탐색 시작점과 관련 자료
- 관련 파일·함수·기존 테스트: 알려진 경로·심볼과 선정 이유. 모르면 미확인으로 적고 첫 검색 범위를 지정한다.
- 재현: 실행 환경·입력·명령, 기대 동작과 실제 동작, 오류 메시지.
- 자료: 원본 로그 경로와 오류 전후·스택 트레이스, 문서 링크와 관련 절만 제공한다. 전체 로그·문서의 중복 첨부를 피하되 진단에 필요한 맥락은 보존한다.

## 2. 목표·범위·비범위
수정할 모듈·허용된 변경 범위·보존할 동작을 지정한다. 기존 사용자 변경과 접근 금지 영역을 기록한다. 같은 목표의 분석·수정·검증은 묶고 독립 작업은 제외·보류한다.

## 3. 설계 결정
구성 요소, 데이터 흐름, 인터페이스, 호환성, 선택 근거와 버린 대안을 설명한다. 필요한 오류 처리와 경계 조건을 결정한다.

## 4. 구현 순서
의존 순서에 따라 테스트·구현·통합을 배치한다. 각 단계에 대상 파일과 완료 기준 ID를 연결한다. 단계별 사용자 재개 승인을 넣지 않는다.

## 5. 완료 기준
각 기준에 ID, 관찰 가능한 결과, 검증 방법을 지정한다. 검사하지 못한 조건은 완료로 표시하지 않는다.

## 6. 검증
실행할 명령, 실행 위치, 성공 기준, 허용된 비용·네트워크 사용, 실패 시 조사 절차를 기록한다. 관련 테스트와 필수 회귀·통합 검증을 구분하되 모두 완료 기준에 연결한다. 검증 명령은 신뢰할 수 있는 내용을 검토한 뒤 실행한다. 원본 로그 보관 경로·보안 정책과 명령별 종료 코드·실패 요약의 기록 방식을 정한다.

## 7. 자율 복구와 중단
작업 전체 복구 시도 상한을 1~10의 정수로 정한다. 예제는 3이다. 최초 실패 이후 수정·재검증을 1회로 센다. 권한·범위 변경 및 해소 불가 차단의 반환 조건을 기록한다. 완료·한도 소진·차단 시에만 결과를 반환한다.

## 8. 상태와 인계
장기 자율 실행의 현재 단계별 작업 맥락과 별도 이력 보관 경로를 정한다. 요약 시 보존할 모든 완료 기준의 상태·미검증·전역 제약·승인 경계·미해결 위험·누적 복구 횟수를 명시한다. 과거 상세 근거를 보관하고 참조를 확인한 뒤 요약하며, 누락된 근거의 재조사·재검증 절차를 정한다. 작업 파일 기준 상대 경로의 상태 파일을 지정한다. 상태 템플릿의 기준별 근거와 다음 행동을 유지한다. 재개는 상태 파일과 필요한 설계 부분만 참조하며 전체 문서를 반복 전달하지 않는다. 재개 시 설계·안전 규칙·관련 파일의 변경 여부를 확인한다. 최종 보고는 기본적으로 변경 이유·수정 파일·테스트 결과·잔여 위험으로 제한하며, 완료 기준별 상태·증거 경로는 상태 파일에, 과거 상세 근거는 별도 이력에 둔다.

## 9. 권한과 비용
push·배포·삭제·비밀정보 접근 등 승인 대상을 명시한다. 실제 모델·예산 설정은 확인된 플랫폼 기능만 사용한다. 사용자 메시지 수와 내부 모델 호출 수를 동일시하지 않는다. 지침만으로 과금 상한이 강제된다고 가정하지 않는다.
