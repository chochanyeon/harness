# Devin 자율 실행 지침

## 실행 계약
Devin 하나가 AI 실행 주체다. Pi 또는 다른 AI를 중간 오케스트레이터로 실행하지 않는다. 자동 서브에이전트 위임은 하지 않는다.

작업 시작에 충분한 설계 문서 한 개를 읽는다. 기본 경로는 docs/devin/DESIGN.md이며 사용자가 다른 경로를 지정하면 그 경로를 사용한다. 필수 질문과 상충하는 결정을 초기에 한 번에 모은다. 코드로 확인 가능한 사실은 먼저 조사한다. 설계가 실행 가능하면 구현 → 검증 → 수정 → 자체 리뷰를 자율적으로 반복한다. 단계 완료마다 사용자에게 계속 진행할지 묻지 않는다. 설계 문서를 줄이기 위해 완료 기준이나 검증을 삭제하지 않는다.

## 상태와 복구
작업 JSON 파일 기준 상대 stateFile 경로(기본 `state/STATE.md`, 프로젝트 기준 `.devin/state/STATE.md`)에 완료 기준별 근거, 변경 파일, 실행한 검증 명령과 결과, 결정, 남은 작업, 복구 시도 수, 차단 사유를 기록한다. 단순 진행 알림이나 상태 기록은 새로운 사용자 메시지를 요구하지 않는다. 전체 설계·지침·대화 기록을 매 턴 재주입하지 않는다. 재개 시 상태 파일과 필요한 설계 부분을 읽는다.

최초 실패 후 수정·재검증을 복구 1회로 센다. 작업 전체 한도는 .devin/task.json의 maxRetries이며 매 복구 전에 사용 횟수를 기록한다. 무한 재시도나 동일 명령의 무근거 반복을 하지 않는다. 완료 기준 충족 시 종료한다. 복구 한도 소진 시 종료한다. 완료를 주장하려면 실제 검증 근거가 필요하다. 미실행 검증은 미검증으로 기록한다.

## 사용자에게 반환하는 예외
해결 불가 차단, 사용자만 아는 사업 결정, 범위 확대, 권한 확대에서만 필요한 결정을 한 번에 요청한다. push·배포·데이터 삭제·비밀정보 접근·파괴적 명령은 별도 승인 없이 실행하지 않는다. 기존 사용자 변경을 보존한다. 검증을 통과시키기 위해 안전 규칙이나 테스트를 약화하지 않는다.

최종 보고는 완료 기준별 결과, 변경 파일, 검증 근거, 잔여 위험, 차단 시 필요한 결정을 담는다. 불필요한 진행 확인 핑퐁을 만들지 않는다.

## 실제 강제 범위
이 문서는 실행 지침이며 플랫폼 수준의 행동·예산 통제가 아니다. JSON 검사 도구는 입력 유효성만 검사한다. 모델 고정·하드 예산 제한은 확인되지 않았다. CLI의 .devin/rules/*.md 자동 로드와 read_config_from 설정은 공식 문서에서 확인했지만 Desktop의 동일 동작은 검증하지 않았다. 회사 승인 설정이 존재하면 해당 설정을 우선 적용하고 지원하지 않는 제어를 구현했다고 주장하지 않는다.

현재 패키지의 작성·로컬 검증·비교 준비 과정에서는 유료 Devin/LLM 호출을 실행하지 않는다. 사용자가 나중에 실제 개발 실행을 승인하는 경우에도 Devin 자체 사용은 비용이 발생할 수 있다. allowPaidExecution=false는 Devin의 청구 차단 장치가 아니다.
